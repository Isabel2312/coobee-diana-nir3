# CooBee: прототип сценария для НИР-3

ДИП, Варава Диана Сергеевна. Демонстрационная реализация подготовлена с помощью ИИ-инструментов. Пользовательское исследование запланировано, результаты не заявляются.

## Что работает

Анкета без регистрации → до 6 идей → карточка с объяснением → сохранение в список → повторное открытие списка. Есть лайк, дизлайк, «уже есть», фильтр бюджета, пустая и запасная выдача, обработка ввода, сохранение в браузере, экспорт событий JSON/CSV.

24 записи — синтетический демонстрационный каталог, а не каталог Нины и не проверенные предложения. Ранжирование детерминированное, по интересам и бюджету. LLM, CatBoost, API магазинов, оплата и настоящий backend не подключены. Ссылки ведут на поиск похожего. Область работы — пользовательский сценарий и измерение его прохождения, а не оценка рекомендательной модели.

## Запуск

Нужен установленный Node.js. В этой папке: `node server.mjs`, затем открыть http://127.0.0.1:4173 . Остановить Ctrl+C. Установка npm-пакетов не нужна.

Исходники веб-приложения находятся в `dist/`. Файлы: `index.html`, `styles.css`, `app.mjs`, `core.mjs`. Для GitHub Pages выбран источник `main /docs`: папка `docs/` — точная копия `dist/` и добавляется в комплект перед передачей.

## Проверка

`node --test tests/core.test.mjs` — автоматические проверки подбора и целостности каталога. Это инженерные тесты, не usability-сессии.

## Сбор логов

1. «Для исследования» → скачать прошлый журнал, если нужен.
2. Выбрать «Пользовательская», нажать «Новая сессия» и подтвердить очистку тестовых данных.
3. «К прототипу» фиксирует `task_start`. С этого момента дать участнику задание.
4. После задания вернуться в раздел исследования и скачать JSON.
5. Сохранить как `P01.json`, заполнить строку таблицы наблюдений, не публиковать реальные записи участников в открытом репозитории.

`node scripts/analyze-logs.mjs P01.json P02.json` вычисляет техническое завершение и время. Самостоятельность прохождения и критические ошибки размечает модератор. Тип demo исключается из пользовательского анализа. Повторные выгрузки одной сессии объединяются по ID.

## Архитектура

Текущая версия: HTML/CSS + JavaScript ES modules; core.mjs — правила подбора и каталог, app.mjs — UI, состояние, события; localStorage — локальное хранение. Логи не отправляются на сервер. При недоступном хранилище выводится предупреждение.

Проектная архитектура из общего питч-дека: React + FastAPI + PostgreSQL, API рекомендательного модуля. Это следующий этап интеграции, а не описание текущего статического прототипа. Контракт будущего запроса: occasion, recipient, budget, interests; результата: item ID, title, price, explanation, URL. Формат API уточняется совместно с DS.

## Материалы исследования

`research/PROTOCOL.md` — методика и задания. `research/OBSERVATIONS.csv` — незаполненный шаблон наблюдений. `research/EVENTS.md` — словарь событий. `research/STATUS.md` — статус и ограничения. `research/SOURCES.md` — основания методики. Скриншоты и техническая проверка добавляются отдельно. Отклонённый командой roadmap не использован.
